# Architecture

Acme is one Go process serving an embedded TanStack Start SPA and its API. Its purpose is to make the stack concrete: the project screens use real GraphQL operations, the browser carries a real session cookie, and Go evaluates real Rego policies before allowing changes.

## Build and runtime

Components use React's APIs and types with TanStack Redact 0.3.1 as their browser renderer. The shared Vite configuration applies the official `redact({ environments: ['client'] })` plugin after Start and the Oxc transforms. Native React renders development HTML and prerenders production loading documents; this preserves Vite's standard handling of Relay's CommonJS server dependencies. The standard Start entry in `web/src/client.tsx` hydrates with Redact's documented `identifierStrategy: 'react'`, matching the server's `useId()` values. React and ReactDOM remain installed for server rendering, package peer contracts, and tooling. Default browser runtime features stay enabled, including context, Suspense, lazy loading, hydration, class error boundaries, and portals. Redact renders synchronously without time slicing; its [compatibility guide](https://tanstack.com/redact/latest/docs/compatibility) describes the differences. Router's native `defaultOnCatch` logs unexpected exceptions for developers while the error view keeps its safe user-facing message; expected API `RequestError` values follow normal recovery UI.

Vite's official React plugin uses `react({ compiler: true })` with `oxc-transform-react` for native React Compiler, JSX, and Fast Refresh. This compiler backend is experimental upstream. The community `unplugin-relay` adapter runs the official Oxc Relay transform as a preceding `pre` plugin, replacing GraphQL tags while preserving JSX for the compiler. Redact resolves `react/compiler-runtime` to its compatible memo-cache implementation. React and Relay use Oxc; Babel remains in ESLint's TypeScript syntax parser and TanStack's internal tooling. The compiler does not replace Relay's store, query bootstrap, or route loaders.

`just build` runs `npm run build:web`, then the native Go build. The frontend step compiles production Relay operations and runs `vite build` with the shared `vite.config.ts`; Go builds `.build/acme` with those assets embedded. The production Relay configuration writes artifacts to the ignored `web/build/__generated__` directory and creates SHA-256 operation IDs with `web/persisted-queries.json`, an ID-to-document map. That command uses `--repersist` and keeps Relay's native additive map, retaining previous IDs for existing tabs and built assets. Reusable `packages/route-adapter/src/static-routes.ts` uses TanStack's public generator metadata to derive Start's prerender entries and the version-3 routing-only `route-shells.json` from the same file routes. Routes own their preload declarations through typed `staticData.preloads`; normal prerendering exports their descriptors in each HTML file. The output has route-specific workspace loading documents for Overview, Projects, Project Detail, New Project, Edit Project, the three Components tabs, and Session. Overview uses `index.html`, and each dynamic project route has one HTML file for all project slugs. Native SPA mode also produces `_shell.html`, a shared public Welcome page and generic fallback, using the build mask `/?_shell`. The production Go `web` package embeds `web/dist/client/` as its public filesystem and the operation map separately as `web.Operations`. `justfile` owns complete Go/web workflows; npm scripts run frontend tools.

At runtime, the Go `routeadapter` package matches the requested route using the generated segment descriptors, while static assets and backend namespaces retain their own handling. Go selects that route's workspace HTML for a signed-in session or the shared public document for a signed-out visit. It executes the requested route's declared initial queries with the original URL bindings and adds their results as private JSON. React renders the GraphQL results in the browser. All documents load one client application. TanStack Router handles subsequent navigation, and Relay sends later requests to the same origin's `/graphql` endpoint. There is no production Node process, runtime React rendering, or per-record HTML build. Unknown frontend paths retain the generic SPA fallback and client-side not-found handling; a recognized project URL with a nonexistent slug resolves through the GraphQL response.

The build adapter and frontend tests use TypeScript. The generator validates supported route patterns during the build. Vitest exercises that generator, Go tests exercise the serving contract, and Playwright tests the built application’s initial HTML and hydration in Chromium. See [Static routing](static-routing.md) for supported route syntax, the hydration contract, and upgrade checks.

`just dev` uses `concurrently` to start the pinned Air binary and Vite without a production build. The private `tools` recipe installs Air with native `go install` into `.build/tools`; Air's dependencies stay outside the application module and the supervisor runs it directly. `just dev-api` runs the API watcher alone. Air's `go build -tags dev` selects `web/assets_dev.go`, which exports nil assets and operations with no embed inputs, and writes `.build/dev/acme`. Air's exit cleanup owns only `.build/dev`, preserving the production `.build/acme` binary and installed tool. `server.New` treats nil assets as API-only mode and returns 404 for frontend paths; the same main, session, authorization, and GraphQL handlers remain in use. A non-nil frontend filesystem still requires valid production files. `dev:web` runs the development Relay compiler before Vite; this also happens when it is run on its own. Vite serves the frontend on its default port 5173 and proxies API/auth requests to Go on port 8080. Its development-only server implementation of `getInitialLayout`, built with `createIsomorphicFn`, forwards the request cookie to Go before serving HTML. It serializes only the layout kind and public provider flags and marks the response `private, no-store`. Its documents have no Go bootstrap; normal browser Relay requests still load development data with full query text. Air rebuilds Go for Go source, Rego policy, and module-file changes; its extension filter and frontend exclusions ignore Relay artifacts and `web/persisted-queries.json`. Frontend query edits therefore preserve the running Go process and its in-memory sessions. A backend restart still resets those sessions and data. Playwright runs the production binary separately on port 4175.

`relay.config.json` generates development artifacts without persistence in `web/src/__generated__`. `relay.config.prod.json` writes persisted artifacts to `web/build/__generated__`, which is ignored and regenerated for production. Each file declares one named project through Relay's native `sources`/`projects` configuration and uses the project `output` field; Relay creates missing output directories. These configurations keep development independent of production persistence. The shared `vite.config.ts` selects development artifacts for the dev server and production artifacts for builds and previews, using the corresponding directory for Oxc Relay and the `@relay` alias. Generated type imports use `@relay`; the transform compiles route-local query tags against that absolute artifact directory in both client and server environments. Only `command === 'build'` loads the route-plan generator; configuration loading imports no production requests and does not read the persisted map. The shared descriptor compiler is checked during development and emits empty metadata without requiring persisted IDs. A production build can run while Vite and the development Relay watcher stay active.

Development Relay compilation and optional native watch commands are documented in the [README](../README.md#commands). [Relay's official guide](https://relay.dev/docs/guides/persisted-queries/) also supports persistence together with watch mode when the server reloads its query map. Acme deliberately uses query text during development so frontend query edits do not require rebuilding the embedded Go process. This is a deployment choice, not a general recommendation against persisted queries in development.

The Air version is pinned in `justfile` and installed with native `go install`, keeping its development dependencies separate from the application's module graph. `.air.toml` selects backend files, excludes frontend dependency/output trees, and requests graceful shutdown before replacing the process on macOS and Linux. Air uses its standard process termination on Windows; both build commands use `-tags dev`. It adds no browser proxy. See the [README commands](../README.md#commands) for combined and separate-process development.

## Initial GraphQL data

Each `route.tsx` defines its `graphql` query tag beside `Route` and its page functions. A route-local `defineRouteQuery<GeneratedOperation>()` declaration owns its request, typed variable bindings, authentication flag, and fetch policy. Its `.loader` supplies native deferred readiness and resolved variables, `.request` serves the native Relay reader, and `.preload` supplies data-only `staticData.preloads`. Generated type imports use `@relay`. `_app` declares the shared Workspace query. Overview, Projects, Project Detail, Edit Project, and Session declare their own page queries. New Project uses the inherited Workspace result. Each declaration specifies whether it needs a session and bindings from path parameters, URL query parameters, or literals. Root's `beforeLoad` collects the matched declarations in parent-to-child order and calls the generic `compileRoutePreloads` in `packages/route-adapter/src/route-preloads.ts`. It resolves each `GraphQLTaggedNode` through Relay's native `getRequest`, validates persisted query IDs, variable names, and path-binding names against declared route parameters and returns only descriptor JSON text, so full Relay request objects stay in route options rather than entering serialized context.

Normal prerendering writes `<script id="route-preloads" type="application/json">` with the protocol `{ version: 1, preloads: [...] }`. Its entries contain only operation IDs, authentication flags, and binding descriptors; `<` is escaped. Go reads each workspace document's metadata at startup and validates it against the embedded operation map before preparing the existing bootstrap handler. The version-3 routing manifest contains no preload entries. The public fallback's metadata must be empty; Go still uses the originally requested workspace route's declarations when serving that public HTML. The root preserves the exact metadata script text during hydration and client navigation.

Generic `VariableBinding` types and `resolveVariables` stay in `packages/route-adapter/src/preloads.ts`. Acme's `projectBindings` and `projectVariables` live in `web/src/features/projects/project-variables.ts` and are shared by the client and route declarations. Projects binds URL `search`, `status`, and `first` to the corresponding GraphQL variables, with defaults of `null`, `null`, and `6`. URL `after` binds the stable GraphQL `anchor`, defaulting to `null`; the initial GraphQL `after` is a literal `null`. Project Detail and Edit Project bind GraphQL `slug` to the `$projectSlug` route parameter. Each declaration applies once per route family. Go obtains concrete dynamic values from the actual request URL. Adding or renaming a page keeps its initial-query declaration with the route. A new project slug needs no declaration or build. See [adding a page](static-routing.md#adding-or-renaming-a-page).

Go decodes query fields in request order using the browser's `URLSearchParams` rules, including literal semicolons, malformed percent escapes, and UTF-8 replacement. The Go-maintained `golang.org/x/text` decoder handles Unicode replacement, while the shared bindings apply their existing integer, boolean, enum, and range validation afterward.

Go executes these reads through the same schema, SCS context, and OPA checks as `POST /graphql`. Signed-out documents include only Workspace data with a null viewer. Signed-in documents also include the declared page result. Components and New Project need only Workspace. Session owns its own query and fragments. The response adds a JSON array of `{ id, variables, response }` in `script#route-bootstrap`, with HTML-sensitive characters escaped. These served documents use `Cache-Control: private, no-store` because their JSON can contain private data. The static build files remain free of user data, and preloads cannot run mutations.

Relay's network layer matches bootstrap responses by operation ID and variables and consumes each response once, when the network execution is subscribed. Relay performs its normal normalization and retains the records in that application instance's store. The preloaded initial batch needs no duplicate browser GraphQL fetch. An expanded Projects URL still bootstraps only that batch, then restores its requested window through normal Relay pagination. After a bootstrap response is consumed, navigation, pagination, and mutation refreshes use the normal network transport. Authentication changes reload the document, creating a fresh bootstrap and Relay environment.

The private npm workspace `@acmekit/route-adapter` has explicit `/vite` and `/runtime` entry points. It owns native route discovery, prerender planning, the routing manifest, typed preload declarations, URL bindings, loader warmup, and bootstrap replay. The Go `routeadapter` package owns manifest matching, metadata validation, variable resolution, bootstrap generation, and static asset serving. Both packages evolve with the versioned contract. Acme keeps authentication, application queries, GraphQL execution and transport, initial-layout selection in `features/auth/initial-layout.ts`, and validation-error presentation configured in `lib/route-query.ts`. The TypeScript package imports no Acme modules. The Go package receives authentication, query validation, and execution callbacks from `internal/server`.

## Client data loading

`getRouter()` creates one Relay Environment for that Router instance. Router context exposes it to loaders, and Router's `Wrap` mounts `RelayEnvironmentProvider` with the same instance. `lib/relay.ts` supplies the GraphQL transport. The shared route-query declaration uses `fetchRouteQuery` from `@acmekit/route-adapter/runtime`, an adapter around native `fetchQuery.subscribe`, to normalize results. The `_app` route awaits its Workspace declaration’s `.fetch` in native `beforeLoad` and returns an `authenticated` boolean in inherited Router context. Private declarations use that context directly, including below intermediate layout routes. The Go target keeps this boundary behind `ssr: false`.

Private declarations expose a native loader that resolves the shared variable bindings once and returns `{ variables, ready }`. Data regions consume the native deferred `ready` promise with `useAwaited` inside Suspense, then pass those same variables to `useLazyLoadQuery`, keeping surrounding headers and controls available. This Router deferral does not introduce GraphQL incremental delivery. Page components use `useLazyLoadQuery` with its default `store-or-network` policy to read the warmed store. A missing or garbage-collected result can still use Relay's normal network/Suspense fallback. There are no application-owned query references or custom query-resource manager; Relay retains mounted readers normally. The adapter collects the response and resolves on completion. Relay's native subscription `start` callback binds cancellation before execution begins, and its `finally` callback removes the abort listener after completion, failure, or cancellation. Abort unsubscribes and resolves `undefined`, letting a still-mounted reader use its normal cache/network fallback. The network Observable's teardown aborts the HTTP fetch. The API returns one complete GraphQL response without incremental `@defer` or `@stream`.

Projects declares `loaderDeps` from GraphQL variables only. The visible `page` count and hash are outside those dependencies. Projects sets native `preload: false` for its data loader so hovering a link cannot replace an expanded connection's range. Native code preloading remains available. Create awaits `router.invalidate({ sync: true })` before returning from its page. Edit uses Relay's normalized mutation merge and `router.clearCache()`. Delete uses `@deleteRecord`, clears cached matches, and navigates to Projects. The transport tracks completed writes within the Environment. If a successful mutation overtakes a pending query, it repeats that read before passing any payload or error to Relay. The write-version check and publication run in the same asynchronous continuation, covering responses that settle together. Retired network executions discard later results and errors. This prevents native in-flight deduplication from reusing a pre-mutation snapshot. Browser checks cover request ordering across cancellation, preloading, and invalidation.

New Project at `/projects/new` and Edit Project at `/projects/$projectSlug/edit` compose the shared `ProjectForm` through native automatic route splitting. Lightweight `ProjectFormLayout` owns the PageHeader's native `h1`, native named form, responsive fields, and pending presentation, keeping validation and mutation code in the split interactive page. Its flat composition is centered within the main content at `max-w-4xl` (896px at the default root size). Fields use native responsive orientation, stacking on mobile and placing an 11rem label rail beside the editor from the FieldGroup's 448px `@md` container threshold. Thin Separators frame the fields and right-aligned action row. The form owns TanStack Form's validation and submission state and reads edit values through its colocated `ProjectForm_project` fragment, which selects `id`, `slug`, `name`, `description`, and `status`. Edit's route owns `ProjectEditPageQuery`, its typed route-query declaration, reader, and authenticated preload metadata. Its loader uses `store-or-network` to reuse normalized project data already loaded by Detail.

The Workspace query composes the account menu's viewer fragment. The menu reads its own fields with `useFragment`; the workspace context exposes only `canManageProjects` for shared action gates. Its sidebar placement adds no query. Session owns its query and viewer/server-info fragments, using the same native loader, deferred data boundary, and Go preload declarations as the other private data pages. This keeps account and session fields colocated without passing complete query responses through context.

## UI structure

The theme defines the semantic palette, light and dark neutrals, self-hosted Archivo headings, and Instrument Sans body text. Shared controls use shadcn's Base UI `base-luma` structure and behavior. UI primitives live in `web/src/components/ui/`. Pages, pending views, query tags, and `Route` live together in each directory's `route.tsx`. Page functions remain unexported for automatic splitting. Reusable feature controls and workspace authentication state live in `web/src/features/`. CSS defines tokens and base rules, and Tailwind utilities compose layouts. The [design-system guide](design-system.md) documents component styles and source attribution.

The workspace adapts shadcn's bordered Sidebar with fixed desktop navigation, a bottom account menu, and a full-screen mobile drawer. Page headings belong to the main content. Desktop has no separate titlebar; mobile has a compact sticky brand/menu row using the opaque sidebar fill. The main view stays flush, and the public sign-in composition is unboxed. Page content uses standard Card, Table, Field, and overlay composition without changing session, permission, or Relay behavior. The [layout guide](design-system.md#workspace-layout-and-loading) owns current dimensions, responsive spacing, and branding.

Overview and Projects share `features/projects/ProjectTable.tsx`. It reads plural Relay fragment references and uses TanStack Table v9's core row model for column definitions and row/cell rendering through the existing shadcn Table primitives. Go's project IDs provide stable row IDs. Relay and Go retain search, status filtering, cursor-based Load more, and mutation refreshes. Session's fixed permissions matrix uses the basic Table directly.

`WorkspaceProvider`, defined in `components/workspace/workspace-frame.tsx`, is mounted in the root route above `Outlet`. It keeps the document's initial layout choice stable through hydration, owns the standard `SidebarProvider` and `TooltipProvider`, and configures the shared sidebar width. `WorkspaceFrame` supplies structure, gutters, and the mobile titlebar with its Open navigation control. The mobile titlebar or desktop content owns the top safe-area inset once. Initial loading and resolved workspaces share the same frame, sidebar, and mobile navigation state across loading transitions. Desktop collapse, rail, and shortcut behavior are disabled in the application.

The `_app` route renders `WorkspaceEntry`, whose Relay reader uses the Workspace result warmed by that route’s native `beforeLoad`. A null viewer renders the complete `features/auth/SignInPage`; an authenticated viewer renders the workspace and outlet. The initial public `ClientOnly` fallback remains the full sign-in page, inert until the interactive entry mounts. There is no separate public sign-in request effect or loading spinner.

Workspace loading follows the actual route and data boundaries. The `_app` route selects `WorkspaceLoading` from `components/workspace/loading.tsx`. Each leaf declares its own `pendingComponent`: `OverviewLoading`, `ProjectsLoading`, `ProjectDetailLoading`, `ComponentsLoading`, or `SessionLoading`. Components shares its normal view with a loading entry that does not read Router state. Native automatic code splitting keeps pending views eager, allowing the complete loading document to hydrate without waiting for lazy page code. Noncritical route components use Router's default lazy splitting. For a workspace document, `WorkspaceLoading` finds the route's pending component through the native route/parent chain rather than inspecting path strings or maintaining a second set of page layouts. TanStack Router supplies the route Suspense boundaries, so `WorkspaceEntry` renders its content and outlet without additional Suspense wrappers.

The workspace loading view renders the real `WorkspaceFrame` and `AppSidebar`. Branding, navigation, and Documentation remain in the same positions after loading; the footer reserves avatar and name placeholders in the same 44px profile row until the viewer arrives. The Demo badge appears in the brand row and mobile titlebar when the Workspace result confirms demo mode; the initial workspace layout hint contains no provider flags, and both rows keep their height. The profile trigger shows the viewer name and chevron; the role stays inside its popup. Its account menu includes identity, Your session, an Appearance radio group with Light, Dark, and System choices directly in the popup, and Sign out. Before `useHydrated` becomes true, the sidebar renders ordinary anchors without active-route styling; afterward it uses TanStack Links and the current route. No viewer or private project data is prerendered at build time; request data travels in the separate bootstrap JSON.

Each workspace shell renders its matched page's loading view from the first HTML response; the public shell renders Welcome. Root loader data records `pendingRouteId` and an `initialLayout` choice. During production prerendering, `getInitialLayout` uses Start's public `getRouterInstance().isShell()` API to record sign-in for the SPA document; ordinary route prerenders record workspace. The query in the SPA mask gives the native build queue a distinct root URL, and application code does not inspect it. For this Go target, the root wraps `Outlet` in the public `ClientOnly` component with `WorkspaceLoading` as its fallback. That fallback selects the same sign-in page or workspace loading view as the served document. The `_app` route retains `ssr: false` to keep private loaders and dynamic child matches outside the prerendered data. The workspace loading view uses the saved route identity during server rendering and the first hydration pass, then uses the browser's actual matched route after hydration. The dynamic build placeholder is absent from the generated HTML and manifest. Go selects complete documents without rewriting Start's serialized state or introducing a second client application.

Loading views share the normal page JSX with absent data, preserving headings, labels, icons, and navigation. They disable controls that require an authenticated session without inventing a viewer or issuing private queries. Overview and Project Detail retain local Relay Suspense boundaries. Overview's New project link remains outside its data boundary once the session is known. Projects keeps its real search/filter controls outside the results boundary. `features/projects/project-loading.tsx` supplies `ProjectsResultsSkeleton`. `ProjectTable` owns its shared loading rows and empty states. New and Edit pending views render the shared form with disabled fields and actions, independently of Workspace context or concrete route parameters. New's initial empty values are known. Edit uses Skeleton only for unknown field values. Resolved read-only visits show a permission message and return action. Project forms leave focus to browser and user interaction on desktop and touch devices. Session uses placeholders for its unknown account and server values. Components renders its actual local controls. Skeleton fills only unresolved values or records, is `aria-hidden`, and disables pulsing for reduced motion. Data regions supply accessible loading status and `aria-busy`. Production requests have no artificial loading delays.

Theme handling uses `next-themes` 0.4.6 through `components/theme-provider.tsx`. This adapts shadcn's documented next-themes approach to Start. The root sets `attribute="class"`, `defaultTheme="system"`, `storageKey="acme-theme"`, `enableSystem`, and `disableTransitionOnChange`. The library emits its initial theme script, maintains the root class and native `color-scheme`, and temporarily suppresses CSS transitions during theme changes. The public sign-in mode toggle, account Appearance choices, Components controls, and Sonner share that provider. It adds no Next.js runtime, Start server function, or Node server to the embedded deployment.

## Ownership of state

| State                                 | Owner                                             | Lifetime                                                                                |
| ------------------------------------- | ------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Current user and role                 | Go session                                        | Until logout, session expiry, or server restart.                                        |
| Session cookie                        | Browser; issued and validated by Go               | Matches the server session lifecycle.                                                   |
| Projects                              | Go in-memory workspace                            | Until the process stops; a new demo login gets new seed data.                           |
| Bootstrap responses                   | The current HTML document and Relay network layer | Each operation and variable set is consumed once.                                       |
| Cached GraphQL records                | Router-owned Relay Environment                    | Normal Relay retention/garbage collection; a document reload creates a new Environment. |
| Routes and committed query parameters | TanStack Router                                   | Browser navigation and history.                                                         |
| Projects search draft                 | React local state                                 | Until its debounced URL commit; navigation cancels pending edits.                       |
| Component-gallery tabs                | TanStack Router path                              | Selected page path, restored by browser history.                                        |
| Dialog visibility                     | TanStack Router hash                              | Named dialog entry, restored by Back/Forward.                                           |
| Color theme                           | Browser preference                                | Across visits in the same browser.                                                      |

The Relay `viewer` query reports the current user. It is the frontend's source of user data, not an authentication credential. The cookie contains an opaque session identifier; the server holds the session data. No React authentication SDK is needed for that boundary.

Components uses native page routes: `/components` selects Controls, `/components/appearance` selects Appearance, and `/components/ai` selects AI Elements. Tab changes push history entries, preserve query parameters, and suppress scroll reset. Each route's pending view includes its selected tab, so direct visits and reloads start with the correct selection in the initial HTML.

New and Edit project entry links use native Router navigation, preserve query parameters, and mark the new history entry with `projectFormSource: true`. Cancel and successful save call `history.back()` when that marker and `useCanGoBack()` identify a source entry. Direct visits use replacement navigation to Projects after New or the canonical project detail URL after Edit, preserving query parameters. Submission checks its mounted form instance and the captured native history key before returning, so a late mutation completion cannot navigate away from a newer entry or a newly mounted form restored by Forward. New and Edit require project-management permission, and Edit also requires an existing project. Legacy `#new` URLs on Overview and Projects and `#edit` URLs on Detail use route `beforeLoad` replacement redirects to their dedicated pages with query parameters preserved.

Interactive pages control public `#login`, Session's `#role`, and the Components example's `#dialog` through `useHashDialog`. Opening pushes a hash entry while preserving query parameters and scroll position. Closing uses Back for an entry opened by the application. Closing a direct link replaces its hash with the page's fallback. The Components dialog uses the default empty fallback hash. Back/Forward restores visibility, and stale asynchronous callbacks cannot close a newer location. Loading views do not call the URL hook and default to closed. Sign-in opens only when a provider is available. Choose a role additionally requires demo mode. Provider-option updates preserve the requested sign-in hash, and successful authentication keeps the existing full-document navigation to `/`.

Projects uses native TanStack Router search parameters for `search`, `status`, `first`, `after`, and `page`. A local search draft keeps typing responsive, then commits through Router navigation after 220ms with history replacement. Enter, status changes, and Clear filters cancel pending debounce work, commit immediately, and push history entries. Navigation cancels a pending search commit, and Back/Forward restores controls from the URL. Relay variables come from the committed Router `location.searchStr` through `projectVariables`; `page` is browser-only state. Filter edits clear `page` and the initial cursor while preserving `first`, unrelated query parameters, and the hash. Query changes leave the toolbar mounted while the existing results Suspense boundary handles data loading.

`page` is a positive accumulated batch count with a default of 1. `first` stays the stable batch size, from 1 to 50, and URL `after` stays the initial anchor rather than changing to the latest cursor. The visible window contains up to `first * page` rows. Load more uses Relay's `loadNext`; only a successful request pushes the next `page` into URL history, while a failure keeps the URL unchanged. Back selects a smaller cached window, and Forward restores the larger window, fetching missing batches if necessary. Reloading or sharing `page > 1` consumes the initial bootstrap batch and then paginates through the normal API until the requested window or the end of the connection. Changing `page` does not change the GraphQL preload variables or initial batch size. This combines [TanStack Router's search-parameter pagination state](https://tanstack.com/router/latest/docs/guide/search-params) with [Relay's connection pagination and `loadNext` completion callback](https://relay.dev/docs/api-reference/use-pagination-fragment/).

GraphQL `anchor` is a stable connection filter alongside search and status. Relay advances only GraphQL `after` during pagination, keeping `anchor` fixed. Initial reads and mutation refreshes use `after: null`, so Relay's native connection behavior replaces the initial batch, including for an anchored URL; normal pagination then restores any expanded window. The public URL parameter remains named `after`.

Router parsing and serialization use native `URLSearchParams`, preserving literal strings and repeated keys rather than interpreting query values as JSON. Both the browser's binding resolver and Go use the first value for a repeated bound parameter. Query and hash changes remain browser navigation; they add no adapter, production server rendering, or Node runtime.

## Authentication flow

### Local demo

`POST /auth/demo` accepts the requested `MAINTAINER` or `MEMBER` role only when the process starts with `--demo`. Demo mode requires a loopback listening address. Each sign-in establishes a session and a fresh seeded workspace, so independent demo sessions do not edit one another's projects.

Role selection intentionally grants the selected demo role without proving an identity. A reverse proxy can make even a loopback listener publicly reachable. This mode is for disposable demo data; real application accounts need the identity and provisioning rules described below.

### GitHub

When both GitHub credentials are configured, `GET /auth/github` starts the OAuth flow. Go stores per-login state and PKCE data, verifies the callback at `/auth/github/callback`, exchanges the code, and requests the GitHub user identity. It then issues an SCS session and redirects to the application.

GitHub identities receive a stable personal workspace within the running process. The template gives every successful GitHub sign-in the maintainer role for that workspace. GitHub login does not make the memory store persistent or implement organization membership.

### Logout

`POST /auth/logout` invalidates the Go session. The frontend reloads after authentication changes, which also discards its Relay environment and cached private records. Hiding the user in the interface alone would not end the server session.

## GraphQL and permissions

The API accepts JSON GraphQL requests at `POST /graphql`. Production Relay requests send `{ id, variables }`; Go resolves the document from the compiler's embedded SHA-256 map. Vite development sends `{ query, variables }` with the full operation text. Raw queries also support tooling and schema introspection, so persisted operations are not an enforced allowlist. The map is supplied as `server.Config.Operations` and is outside the public static filesystem.

API calls and bootstrap reads use the same `executeGraphQL` path around native `graphql.Do`. The library parses, validates, and executes each request with its variables and context. Persisted IDs resolve to the compiler’s query text.

GraphQL and REST error codes and HTTP 401 status remain on `RequestError` until rendering, including bootstrap failures and mutation callbacks. Page errors, inline/dialog alerts, and error toasts share `ErrorMessage`, which offers a normal `<a href="/">` for `UNAUTHENTICATED` or HTTP 401. Clicking it starts a fresh document and Relay environment. `FORBIDDEN` and HTTP 403 remain permission errors and do not prompt sign-in.

Expected request and URL-validation errors use `RequestError` for user-facing messages. Unexpected JavaScript exceptions render a generic retry message through the same shared renderer, preserving their original messages and stacks for developer diagnostics. Legacy sign-in instructions retain recovery links using normalized copy. The page error view offers a full document reload to clear a caught exception and start a fresh bootstrap and Relay environment.

Go applies the same GraphQL error boundary to API calls and initial page data. Intended `graphError` messages and codes remain actionable, including sign-in recovery. Unexpected resolver errors and panics caught by the GraphQL executor are logged and replaced with a generic `INTERNAL_ERROR`; partial data and public error locations remain intact. The transport sends GraphQL errors to Relay's error callbacks, so mutation components handle them once through `onError`. Query admission uses the GraphQL library's lexer before parsing, retaining the structural nesting and selection limits without a second string/comment parser.

Each operation receives one JSON response; the transport does not use incremental `@defer` or `@stream` delivery. Authenticated views use Suspense to reveal data supplied by bootstrap or HTTP; the public sign-in page updates its provider options without suspending. Public metadata includes `serverInfo`; `viewer` is nullable for signed-out requests. Project reads and writes use the authenticated workspace.

The schema implements global IDs, the `Node` interface, and cursor connections for Relay. Mutations use input/payload objects and support `clientMutationId`. The project list supports search and status filters.

`Project.slug` supplies human-readable detail URLs such as `/projects/atlas-design-system`. The store allocates a slug once from the project's name, makes it unique within its workspace with suffixes such as `-2`, preserves it on rename, and reserves it after deletion for that workspace's lifetime. The `new` slug is reserved for the creation page, so a project named New receives `new-2`. The `/projects/$projectSlug` route runs `ProjectDetailPageQuery($slug: String!)` using `project: projectBySlug(slug: $slug)`. Edit uses the same resolver through `ProjectEditPageQuery`. That resolver applies the same read authorization and workspace boundary as ID lookups. Missing slugs return `null`. Opaque Relay `id` values remain the normalized record identity and the arguments for `node`, `project(id:)`, and mutations. As a compatibility fallback, `projectBySlug` accepts a valid legacy encoded project ID from the same workspace. After it resolves, native Router navigation replaces Detail or Edit's URL with that page's canonical slug path while preserving query parameters and hash.

`graphql-go/graphql` builds the executable schema in Go. The matching SDL in `schema.graphql` is the Relay compiler's contract. A schema change must update both representations, then regenerate the frontend artifacts.

Go checks the current session and uses the embedded OPA policy for the requested action. Members can read; maintainers can also create, update, and delete. The frontend's `canManageProjects` value makes the interface reflect those decisions. The mutation handler still checks permissions even if a caller bypasses the interface and sends GraphQL directly.

The policy evaluator runs inside the Go process. There is no OPA daemon to start.

## Browser request boundary

SCS handles opaque `HttpOnly` cookies. `ACME_PUBLIC_URL` determines the external origin and whether cookies require HTTPS. Go's `http.CrossOriginProtection` checks state-changing browser requests. The API accepts mutations through POST; OAuth callback state and PKCE are validated separately from that middleware.

The embedded deployment keeps the application and API on one origin. If you add a proxy, configure `ACME_PUBLIC_URL` for the browser-facing origin and forward the request metadata used by the origin checks. Preserve `Cache-Control: private, no-store` on HTML responses because their bootstrap data can include the authenticated user's data.

## Testing

The backend uses Go’s standard `testing` package, `net/http/httptest`, cookie jars, and `fstest.MapFS`. Tests cover authorization, session rotation and logout, workspace isolation, CRUD, pagination, input and request validation, OAuth state and PKCE, static routing, persisted operations, and request bootstrap. They run against in-process handlers and temporary HTTP servers without a database or external identity service.

The API-only `dev` Go variant has no frontend-build requirement; the production variant needs the embedded frontend and operation map. Vitest covers the TypeScript route generator and bootstrap replay. Development TypeScript checks use development Relay artifacts without writing them; production checks include E2E code and require production artifacts.

Playwright Test uses TypeScript in `web/e2e/`. Its `webServer` configuration launches the real `.build/acme` with demo mode and shuts it down after the tests. Browser tests cover maintainer CRUD and logout, member views, each fixed loading layout, multiple dynamic project URLs, URL filters, and not-found handling. They distinguish the static layout from private bootstrap JSON, check the cache policy and exact variables, and require preloaded pages to hydrate without browser GraphQL fetches. A mutation from a preloaded Projects page must still refetch fresh data. Browser errors fail the tests. A Playwright API test compares the running Go schema with `schema.graphql` using the GraphQL library.

Use the [README full validation sequence](../README.md#testing-the-built-application) for the current build, type-checking, race-test, browser installation, and E2E commands.

## Extension points

### Persistent storage

Replace the project memory store with a repository backed by a database, while keeping the GraphQL contract stable. Give identities and workspaces durable IDs and scope each repository operation to the authenticated workspace.

Replace SCS's in-memory store independently. With PostgreSQL, SCS provides `github.com/alexedwards/scs/pgxstore` for a native pgx pool and `github.com/alexedwards/scs/postgresstore` for `database/sql`. Create the session table through migrations before enabling that store.

### Application identity

Replace the demo role selector and the default GitHub maintainer assignment with your application's provisioning rules. Derive roles and workspace membership in Go and pass trusted facts into OPA. Add identity providers at the server authentication boundary.
