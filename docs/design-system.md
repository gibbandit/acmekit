# Acme design system

Acme pairs Archivo headings with Instrument Sans body text and shadcn's Base UI `base-luma` controls. Buttons use solid fills or thin outlines with color-based feedback. Fields use matte fills, and opaque content panels use a single border. Floating popups use an edge highlight and a soft shadow. Navigation uses translucent neutral fills that follow the theme.

## Source ownership

`web/src/styles/theme.css` defines the light and dark tokens, blue primary, font families, typography roles, and Tailwind mappings. `web/src/styles.css` imports the theme and Fontsource CSS and defines the dark variant and shared border and outline reset. The root markup sets the document background and typography. Route files compose primitives from `web/src/components/ui/` with Tailwind utilities. Shared project and authentication controls live in `features/`, and the shell lives in `components/workspace/`. `components.json` records the Base UI Luma configuration and aliases.

The shared theme maps `--primary` to `--palette-blue-solid`, `--primary-hover` to `--palette-blue-hover`, and `--primary-foreground` to white in both themes. Sidebar primary colors and the first chart color refer to the primary token. Navigation selection and logos use neutral colors. Focus rings use the readable blue companion, including its lighter dark-mode value.

## Reusing UI components

To reuse the UI primitives, include `components/ui/`, `hooks/use-mobile.ts` for the Sidebar, the shared theme CSS and its global setup, and the Fontsource dependencies and imports. Retain the font licenses and applicable upstream copyright and license notices. Sonner also requires `next-themes`. ESLint checks that the UI primitives avoid dependencies on application routes, features, and data loading.

Vite resolves both packages' font URLs and emits hashed font assets. The root document imports their Latin WOFF2 URLs through Vite for preloading.

The name-limit hint sits below its label, and validation errors sit below their controls. Description retains a fixed four-row textarea and character counter. Status fills the mobile column and uses a compact maximum width of 13rem from the same container threshold. Thin native Separators run above the fields, between them, and before the action row. The `data-slot="form-actions"` row groups Cancel and Create project or Save changes at the form's right edge. The shared `ProjectForm` preserves validation feedback and inline mutation errors. TanStack Form's `isSubmitting` disables fields, labels, and actions through the mutation and subsequent refresh. The submitting action overlays its spinner while preserving the label's dimensions and accessible name. Pending views retain this composition with disabled controls. New's empty values are known, while Edit uses Skeleton for unknown values. Pending markup works independently of Workspace context and concrete route parameters. Read-only visits render an Empty permission message with a return action. Project form inputs acquire focus through user interaction on desktop and touch devices.

## TanStack Start dark mode

`components/theme-provider.tsx` wraps `next-themes` 0.4.6 using shadcn's [next-themes integration](https://ui.shadcn.com/docs/dark-mode/next). The root retains `suppressHydrationWarning` and configures `attribute="class"`, `defaultTheme="system"`, `storageKey="acme-theme"`, `enableSystem`, and `disableTransitionOnChange`.

The root theme class supplies the same semantic variables to normal content and portals. The public sign-in mode toggle, account menu's Appearance choices, Components appearance choices, and Sonner share this provider. It handles preference persistence, system appearance, native `color-scheme`, and coordinated theme changes without a Next.js runtime.

The root viewport uses `viewport-fit=cover`. The root HTML, body, sign-in view, and workspace share the background token, with document classes owned by the root markup. Sign-in uses `min-h-dvh` to fill the changing viewport. Backgrounds reach the viewport edges. The sidebar, page gutters, public views, dialogs, and toasts protect controls with CSS safe-area insets. `WorkspaceFrame` applies the top inset once through the mobile titlebar or desktop content, using the same frame for loading and resolved views. Portaled dialogs apply their safe gutters once at the Viewport.

Project table headers sit in normal flow inside the horizontal scroll container.

Dialog, AlertDialog, and Sheet position the body relatively and use absolute backdrops under `@supports (-webkit-touch-callout: none)`. `inset-0` covers the document, including content beneath Safari's bars after scrolling. Backdrops use the shared translucent black dimming layer, and popup faces use the shared opaque fill, rim highlights, and elevation.
