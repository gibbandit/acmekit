# Static routing

Acme serves a public sign-in page for signed-out visits and page-specific workspace loading HTML for signed-in sessions from the Go binary. It adds the request's initial GraphQL responses as JSON, then hydrates one React application. Fixed workspace routes get their own HTML entries; a dynamic route gets one reusable entry for its whole URL pattern. Project slugs created after the build work without rebuilding or generating another file.

The built files contain only public markup. A served document can also contain private session and project data in its bootstrap script and uses `Cache-Control: private, no-store`. Go executes the initial queries, while React renders their results in the browser through Relay. Workspace HTML remains a loading layout; this does not render project content for search engines or require a production JavaScript server.

## Generated output

The generated `web/dist/client/route-shells.json` describes these workspace entries:

| URL                           | HTML file                          | Initial layout                                     |
| ----------------------------- | ---------------------------------- | -------------------------------------------------- |
| `/`                           | `index.html`                       | Overview cards and recent-project table.           |
| `/projects`                   | `projects/index.html`              | Project list and controls.                         |
| `/projects/new`               | `projects/new/index.html`          | New-project form with disabled controls.           |
| `/projects/:projectSlug`      | `_routes/<pattern-hash>.html`      | Project-detail layout without a loaded project.    |
| `/projects/:projectSlug/edit` | `_routes/<pattern-hash>.html`      | Edit-project form with unknown-value placeholders. |
| `/components`                 | `components/index.html`            | The local component gallery.                       |
| `/components/appearance`      | `components/appearance/index.html` | Appearance choices with the correct tab selected.  |
| `/components/ai`              | `components/ai/index.html`         | AI Elements selected, with a loading preview.      |
| `/session`                    | `session/index.html`               | Session layout without account data.               |

Native SPA mode also produces `_shell.html`, the shared public Welcome page and manifest fallback. Go serves this document for signed-out visits to declared routes, retaining the requested route's preload declarations and original URL variables. The hash derives from the URL pattern, not a project slug. All entries reuse the same client entry and stylesheet. Normal client navigation keeps TanStack Router and the existing Relay environment; it does not fetch a different HTML document for every route change.

Detail and edit URLs use stable, workspace-unique `Project.slug` values, such as `/projects/atlas-design-system` and `/projects/atlas-design-system/edit`. Duplicate names receive suffixes such as `-2`, renaming preserves the slug, and deleted slugs remain reserved for the workspace's lifetime. The `new` slug is reserved for the static New project page, so a project named New receives `new-2`. Opaque Relay IDs still identify records for node lookups and mutations. Legacy encoded-ID detail and edit URLs resolve only within the current workspace, then the browser replaces them with the canonical slug on the corresponding page using native Router navigation, preserving query parameters and the hash. Go does not redirect these requests.

Components tabs use native nested page routes: `/components`, `/components/appearance`, and `/components/ai`. Each pending view supplies its tab explicitly to the shared frame, so Go serves HTML with the correct tab already selected. The AI page's loading cards keep its chat implementation out of the initial bundle on other pages. Links retain unrelated query parameters and browser history, with no tab query parameter. URL hashes are not sent to Go and remain reserved for browser-only dialogs and anchors.

New project and Edit project use native page Links to `/projects/new` and `/projects/$projectSlug/edit`, preserving query parameters and setting `projectFormSource` in history state. Cancel and successful submission use native Back when that source marker and `useCanGoBack` allow it. A direct New visit replaces its entry with `/projects`, and a direct Edit visit replaces it with canonical project details. Async submission checks its mounted form instance and native history entry key before returning so a completed mutation cannot navigate away from a newer entry or a newly mounted form restored by Forward. Legacy `#new` URLs on Overview and Projects and `#edit` on project details use native `beforeLoad` replacement redirects to these pages, preserving query parameters. Hashes reach only the browser, so Go initially serves the legacy URL's underlying page.

Public `#login`, `/session#role`, and `/components#dialog` follow the browser-only dialog boundary. Initial loading HTML keeps them closed without reading Router state. After hydration, interactive pages open them when the required provider or permission is available. Opening pushes history while preserving query parameters, and closing returns to the owned prior entry or replaces a directly linked hash with its fallback. Successful sign-in navigates to `/` without the dialog hash.

## Build and hydration contract

`vite.config.ts` shares native `srcDirectory` and `router` settings between Start and the adapter. The adapter accepts the same route directory, route/index tokens, ignore rules, virtual route configuration, and generator plugins. Its discovery output stays separate from the live generated route tree. Backend reservations are supplied by the application.

[`packages/route-adapter/src/static-routes.ts`](../packages/route-adapter/src/static-routes.ts) runs the public `@tanstack/router-generator` APIs and consumes their route metadata. It does not parse route filenames itself or import application components. `createStaticRoutes(root)` returns typed Start `pages` entries and a version-3 routing-only manifest with the native path `pattern`, HTML `file`, `routeId`, and portable `segments` for each route. The adapter uses initialized native route metadata to parse parameters and checks each representative URL with TanStack before prerendering it. Index patterns retain their trailing slash in metadata, while served URLs use Acme’s no-trailing-slash convention. The `/vite` entry’s `createRouteAdapter(root)` combines that plan with a Vite plugin that emits the manifest in the client build. The shared `vite.config.ts` calls it only for the build command and passes its pages into Start’s public prerender configuration. Development and preview do not rerun route-plan discovery. Query declarations are colocated in route options and exported by normal prerendering; configuration loading imports no production request artifacts and does not read the persisted map. There is no separately maintained route-to-query registry or Go route list.

The root URL is an explicit `pages` entry that outputs `index.html`. Start's native SPA mode uses `/?_shell` as its build mask and independently produces the generic `_shell.html` file. The distinct query lets its prerender queue process both root documents while matching the existing root route. Application code does not inspect the query marker. All route entries have explicit output paths, crawling disabled, and sitemap exclusion. A dynamic entry renders at a build-only `__route_shell__` parameter; no real record is looked up. If the route tree has no root page, the normal unmatched-root fallback serves the generic shell.

The `_app` route has `ssr: false`, keeping private workspace loaders and dynamic child matches outside the prerendered data. For the Go target, the root wraps `Outlet` in the public `ClientOnly` component with `WorkspaceLoading` as its fallback. Root loader data contains `pendingRouteId` and `initialLayout`, selecting sign-in or workspace markup consistently during hydration. During production prerendering, `getInitialLayout` uses Start's public `getRouterInstance().isShell()` API to choose sign-in for the SPA document; ordinary route prerenders record workspace. For example, the project shell records `/_app/projects_/$projectSlug`, and the Overview shell records `/_app/`. A route identity names a layout and contains no concrete project slug.

`WorkspaceProvider` preserves the document's initial layout choice through hydration and the session request. For a workspace document, `WorkspaceLoading` uses the saved route identity on the server and during initial hydration, selecting the same page loading view in both places. After hydration, the actual browser URL determines the matched route. A public document renders the complete `SignInPage`; its initial fallback is inert until the client entry mounts. The prerendered project shell contains no serialized dynamic child match, and the build-only parameter is absent from both HTML and the manifest. Go selects a complete prebuilt document and adds a separate data script without rewriting Start's serialized state or rendering React.

The native `_app` `beforeLoad` awaits its Workspace declaration’s `.fetch` in the Router's Relay Environment and returns an `authenticated` boolean in inherited context. `WorkspaceEntry` reads the warmed result and renders either the full sign-in page or the authenticated workspace. Private declarations check that context before querying, including below intermediate layouts. The public pending view remains the full sign-in page without a spinner or a separate sign-in request effect. These loaders consume matching Go bootstrap responses in production and use normal HTTP in development.

Router context and provider `Wrap` share one Environment created by `getRouter()`. Loaders warm its normalized store; components read it through default `store-or-network` `useLazyLoadQuery`, which can fetch missing data normally. No retained query-reference layer or custom resource manager is added. `fetchRouteQuery` uses native `fetchQuery.subscribe`, waits for completion, and binds disposal to the loader's abort signal; network Observable teardown aborts the HTTP fetch. An aborted warmup resolves `undefined`, allowing the mounted reader's normal fallback. The API still returns one response without incremental `@defer` or `@stream`. Native navigation reloads coordinate later reads; Projects' `loaderDeps` includes GraphQL variables, excluding browser-only `page` and hash state. Projects disables data preloading with native `preload: false` so hovering cannot reset an expanded connection, while code preloading remains native. Create synchronously invalidates loaders, edit merges its mutation result and clears inactive Router matches, and delete uses `@deleteRecord`, clears matches, then navigates. Request counts and ordering across preloading, cancellation, and navigation remain browser-validation concerns.

Loading views share the normal page JSX. The sidebar, logo, and global controls remain real components; placeholders cover unresolved account and project data. New and Edit compose lightweight shared field and Card presentation from `ProjectFormLayout`, keeping the interactive form's validation and mutation code in the automatically split page component. Pending controls are disabled, New retains its known empty values, and Edit uses Skeleton for unknown field values. Inputs acquire focus through user interaction on desktop and touch devices. When adding a private page, declare its `pendingComponent` and keep that loading view independent of a session or a concrete parameter value.

## Initial data and persisted operations

The production Relay compiler uses `relay.config.prod.json` to write SHA-256 operation IDs into `web/build/__generated__` and a matching ID-to-document map in `web/persisted-queries.json`. The native project `output` setting lets Relay create the artifact directory; it is ignored and rebuilt before bundling. Development uses its own configuration so it does not require production outputs or persistence. Go embeds the map separately as `web.Operations`, supplied to `server.Config.Operations`. It is outside `web/dist/client` and the public static filesystem. The same compiled documents serve production browser requests and initial page reads.

Relay updates this map additively. The `relay:production` npm script uses `--repersist` so the current artifacts' entries are present, while retaining earlier IDs for existing tabs and built assets. `npm run build:web`, and therefore `just build`, use that production command. Regeneration does not reset the map. API calls and bootstrap reads resolve persisted IDs to their query text and use the shared native `graphql.Do` execution path.

Each `route.tsx` owns its `graphql` query tag, native loader, `staticData.preloads`, and page functions. One typed route-query declaration provides `.loader`, `.preload`, and `.request` for the native loader, metadata declaration, and component reader. Generated response types use `@relay`; Oxc Relay selects development or production artifacts through the isolated compiler output paths. `_app` declares Workspace once for its descendants. Overview, Projects, Project Detail, Edit project, and Session declare their page queries. New project uses only the inherited Workspace result. Root's `beforeLoad` receives the matched route metadata even beneath `_app`'s `ssr: false` boundary and collects declarations in parent-to-child order.

[`packages/route-adapter/src/route-preloads.ts`](../packages/route-adapter/src/route-preloads.ts) provides the type augmentation and generic `compileRoutePreloads` helper. During production prerendering it resolves each `GraphQLTaggedNode` with native Relay `getRequest`, validates query IDs, variable names, and path bindings against declared route parameters, then serializes only operation IDs, authentication flags, and bindings. Query request objects remain in route options; root context contains only the resulting JSON string. Development emits empty metadata and needs no production IDs or artifacts.

Each document contains `<script id="route-preloads" type="application/json">` with a `version`, a `preloads` array, and an optional `preloadTimeoutMs`. The compiler escapes `<` to protect script boundaries. Go reads the original workspace HTML's metadata once at startup, rejects malformed metadata, and validates operations against its embedded map before preparing the bootstrap handlers. `route-shells.json` version 3 contains routing only, with no `preload` fields. The public SPA document must have empty metadata; serving it for a signed-out visit still uses the requested workspace route's declarations. Root reads the exact document metadata text during hydration so a public document served at a dynamic URL remains unchanged.

Generic `VariableBinding` types and `resolveVariables` remain in [`packages/route-adapter/src/preloads.ts`](../packages/route-adapter/src/preloads.ts). Acme's project bindings and client helper live in [`web/src/features/projects/project-variables.ts`](../web/src/features/projects/project-variables.ts), independently of generated requests. Project Detail binds `slug` to the actual request's `projectSlug` path parameter and queries `project: projectBySlug(slug: $slug)` through `ProjectDetailPageQuery($slug: String!)`. Edit project uses the same path binding in its colocated `ProjectEditPageQuery($slug: String!)`, selecting `id`, `slug`, and `...ProjectForm_project`. The form owns that fragment's fields and reads it with `useFragment`. Edit's deferred loader uses `store-or-network` to reuse normalized detail data, and its authenticated preload declaration lets Go bootstrap direct edit visits. Projects uses these bindings:

| URL input | GraphQL variable | Initial value                                                 |
| --------- | ---------------- | ------------------------------------------------------------- |
| `search`  | `search`         | Trimmed text, default `null`.                                 |
| `status`  | `status`         | Accepted status, default `null`.                              |
| `first`   | `first`          | Integer from 1 to 50, default `6`.                            |
| `after`   | `anchor`         | Initial cursor anchor, default `null`.                        |
| None      | `after`          | Literal `null`; Relay advances this cursor during pagination. |
| `page`    | None             | Browser-only batch count, default `1`.                        |

The client uses the same application binding definitions so its first Relay request matches the server response. Concrete slugs and query values come from the request, not from the build configuration or prerender placeholder. The public cursor parameter remains named `after`; only its GraphQL binding is named `anchor`.

TanStack Router uses the native `URLSearchParams` parser and serializer in [`web/src/lib/search-params.ts`](../web/src/lib/search-params.ts). Query values remain literal strings, including quoted text, JSON-looking text, and numeric-looking text. Repeated keys retain their order; shared bindings use the first value, matching Go. This keeps the initial browser variables aligned with the original request and its consume-once bootstrap response.

After hydration, Projects uses native TanStack Router query state. Its `validateSearch` checks the URL inputs, `Route.useSearch()` supplies typed values to the page, and `loaderDeps` derives only GraphQL variables. Its local search draft updates immediately and replaces history after a cancellable 220ms debounce; Enter, status changes, and Clear filters commit immediately and push history entries. Navigation cancels pending search edits, and Back/Forward restores the URL's control values. Filters clear `page` and `after`, preserving `first`, unrelated parameters, repeated values, and the hash. Loading views remain independent of browser query state. This adds no production server rendering or Node runtime to the Go SPA target.

The browser-only `page` parameter is a positive accumulated batch count, defaulting to 1. It selects up to `first * page` visible rows without becoming a GraphQL variable or changing the initial bootstrap bindings. `first` remains the stable batch size (1–50), and URL `after` remains the initial cursor anchor. Load more uses Relay pagination and pushes the next `page` only after success; failure leaves the URL unchanged. Back/Forward selects the corresponding cached window, requesting missing batches when needed. A reload or shared expanded URL bootstraps only the initial batch, then restores the requested window through normal browser GraphQL pagination until enough rows arrive or the connection ends. It does not populate React HTML on the Go server. See [TanStack Router search-parameter pagination](https://tanstack.com/router/latest/docs/guide/search-params) and [Relay's `loadNext` API](https://relay.dev/docs/api-reference/use-pagination-fragment/).

The stable GraphQL `anchor` participates in the Relay connection filters alongside search and status. Pagination advances GraphQL `after` while leaving that anchor unchanged. Initial reads and mutation refreshes start with GraphQL `after: null`, letting Relay replace the initial connection batch through its native behavior rather than appending to stale anchored results. An expanded `page` window is then restored through normal pagination.

On a document request, Go loads the current SCS session and executes the declared queries through the existing GraphQL schema and authorization policy. Signed-out requests receive only Workspace data, with `viewer: null`. Signed-in requests also receive the page's declared data. Components and New project need only the Workspace result. Edit project and Session declare their own authenticated queries and fragments. Preloads cannot execute mutations.

The response includes `<script id="route-bootstrap" type="application/json">` containing an array of `{ id, variables, response }` entries. JSON encoding escapes HTML-sensitive characters. The document is private and must not be stored in a shared cache. The bootstrap contains query results, never the session cookie or OAuth credentials.

Acme sets the default `staticData.preloadTimeoutMs` to `1000` in `web/src/routes/__root.tsx`. A route can override it in `staticData` alongside `preloads`. The deepest matched setting applies to all preloads for the document, and `0` disables the extra deadline. The production build embeds the effective limit with the query declarations in `route-preloads`. Go uses it as one shared request-context deadline and serves the loading HTML with completed responses. Relay fetches unfinished queries through the regular API, which still uses its eight-second execution timeout.

Relay's network function consumes each matching operation ID and variable set once, using that response to populate its normal normalized store. Preload metadata uses the compiled Relay defaults for null or missing variable values, so the server uses the same variables as Relay. Go skips entries it cannot encode as JSON, and the browser skips malformed response envelopes. Queries without a usable entry go through `/graphql`; valid embedded GraphQL errors reach the normal error UI. An expanded `page` window uses normal pagination requests to restore its later batches. Subsequent navigation, pagination, and mutation refreshes use the normal network path. Production requests send `{ id, variables }`; Go resolves the document from the embedded operation map. Raw `query` requests support Vite development, tooling, and schema introspection, so this is not an enforced operation allowlist.

Vite development has no Go-injected bootstrap and sends full query text. Before serving development HTML, the server implementation of `getInitialLayout` uses `createIsomorphicFn` to forward the request cookie to the Go API and choose sign-in or workspace markup. A native fetch timeout bounds this layout hint; failures use the existing public fallback while the browser's normal Relay request supplies recovery UI. Only the layout kind and public provider flags enter root loader data, never viewer or project data; this is a presentation hint, not authorization. Development HTML uses `private, no-store`, and normal browser Relay HTTP requests still load its data. The production prerender branch makes no API request.

`relay.config.json` disables persistence and writes development artifacts to `web/src/__generated__`; `npm run relay` regenerates them after operation edits. The `dev:web` command compiles these artifacts before Vite, including when run on its own. `just dev` starts Air and Vite without a production build. Air uses `-tags dev`, selecting an API-only Go build with no frontend or operation-map embeds, and excludes Relay outputs from its watcher. Frontend query edits therefore do not restart Go or reset the session.

The development and production artifact directories are separate, so a production build can run while Vite and the development Relay watcher remain active. Optional `npm run relay:watch` invokes Relay's built-in watcher and is the only workflow that requires Watchman. Acme's development query-text policy avoids having to reload an embedded map; Relay also supports persisted queries with watch mode, as described in [its official guide](https://relay.dev/docs/guides/persisted-queries/). E2E tests exercise the production build and bootstrap path.

## Go serving

[`routeadapter/static.go`](../routeadapter/static.go) reads the embedded routing manifest and each HTML file’s preload metadata at startup. It matches portable static, required, optional, and splat segments using TanStack’s positional specificity and affix precedence. Go accepts routing manifest version 3 and rejects malformed metadata and duplicate matching shapes. Path-binding names must exist in the declared segments, including optional parameters absent from the current URL. Acme supplies reserved backend paths, authentication, operation validation, and GraphQL execution through `routeadapter.Options`. For a declared route, session state selects its workspace document or the shared public fallback. Bootstrap handling still uses the requested route and original parameters, validates bindings before executing queries, and appends request data to the selected document. It does not render React components or maintain Go templates for the page body.

Backend paths stay outside frontend fallback handling. Existing static files are served normally, and missing files under asset or internal shell namespaces return 404. For an unmatched frontend URL, Go serves the generic shell and TanStack Router renders the client-side not-found page; that fallback response is still HTML with HTTP 200. A matching detail URL whose project does not exist returns a null project through GraphQL, including during preload, and the application renders its project-not-found view.

JavaScript, CSS, and SVG responses negotiate gzip or identity and include `Vary: Accept-Encoding`. Hashed assets keep their immutable cache policy. Native `http.ServeContent` serves the selected bytes, including matching HEAD metadata; range requests use the original identity representation. Compression uses Go's standard library on request, with no extra build output or variant cache. Private bootstrap HTML and API responses keep their existing behavior.

## Supported routes

The adapter derives fixed paths, pathless layouts, route groups, index routes, and non-nested routes from TanStack’s metadata. It supports whole-segment `$name` parameters, `{-$name}` optional parameters, terminal `$` splats, and required or optional parameters with prefixes and suffixes. Affixed splats can capture multiple segments before a suffix. Go keeps omitted optional values distinct from present empty captures. Named path bindings use decoded values, and splats use `_splat`.

Matching compares static, required-parameter, and optional-parameter positions, then index and depth specificity, preserving native affix ordering for ties. Crossing overlaps and optional-presence alternatives are covered by differential tests against the installed TanStack Router. This contract uses Acme’s global `caseSensitive: true` setting. Executable route matching callbacks such as `params.parse`, route-specific case overrides, and URL rewrites require a separate integration decision because discovery consumes metadata without executing application route modules.

Literal segments and affixes currently accept ASCII letters, digits, dots, underscores, hyphens, and tildes. Repeated parameter names and duplicate matching shapes fail generation. Acme supplies its backend reservations through the build entry’s `reservedPaths` option and Go’s `ReservedPaths` option. Internal asset and shell namespaces stay reserved by the adapter. Representative URLs are checked against native matching before their HTML is assigned to a family. Fully shadowed patterns need no shell of their own. An unresolved representative fails the build with a diagnostic.

## Adding or renaming a page

Create a directory route such as `routes/_app/reports/route.tsx`. Keep its `graphql` query tag, exported `Route`, page function, and pending function in that file, following the native TanStack examples. Query names remain descriptive and unique; import generated response types through `@relay`, and reuse the query constant for the loader, reader, and `staticData.preloads`. Keep page and pending functions unexported so automatic code splitting can work. Shared controls belong in features or shared components. Render the page heading in the shared page and pending markup.

Declare the operation once with the Acme-configured `defineRouteQuery` from `@/lib/route-query`. It uses the shared package’s `createRouteQueries` factory to keep application error presentation outside the adapter. Here `projectRequest` is the route's native `graphql` tag, and `ProjectDetailPageQueryType` is its generated operation type.

```tsx
const projectQuery = defineRouteQuery<ProjectDetailPageQueryType>()({
  request: projectRequest,
  authenticated: true,
  variables: { slug: { source: 'path', name: 'projectSlug' } },
})

export const Route = createFileRoute('/_app/projects_/$projectSlug')({
  loader: (args) => projectQuery.loader(args),
  staticData: { preloads: [projectQuery.preload] },
  component: ProjectDetailPage,
  pendingComponent: ProjectDetailLoading,
})

function ProjectDetailData() {
  const { ready, variables } = Route.useLoaderData()
  useAwaited({ promise: ready })
  const data = useLazyLoadQuery<ProjectDetailPageQueryType>(
    projectQuery.request,
    variables,
  )
  // Render the page's data here.
}
```

The declaration checks binding keys, scalar types, enum choices, and defaults against the generated variables. Inline path-binding names remain literal, and the native `loader: (args) => projectQuery.loader(args)` call checks those names against the route's actual parameters. Runtime checks cover the compiled operation and required path values. For optional path parameters, declare an explicit `default`, using `null` for a nullable variable. That permits absence while preserving native parameter-name checking at the loader call site. Queries without variables can omit `variables`. The shared resolver validates incoming values and supplies the same variable mapping to Go metadata and the browser. The helper has one type assertion at this checked decoding boundary because runtime object construction erases mapped key types.

`_app` supplies inherited authentication context through native `beforeLoad`. A declaration with `authenticated: true` requires that context and skips private reads for signed-out visits. `.fetch` supplies a blocking response for Workspace, while `.loader` supplies native deferred readiness for page regions. Workspace and Edit use explicit `fetchPolicy: 'store-or-network'`. Other page declarations use `network-only` to refresh their data.

Keep the data region under Suspense and read `ready` before the native Relay reader, so a refresh finishes before cached data is presented. Share application bindings with the browser's variable parser, as Projects does through `features/projects/project-variables.ts`, and use only query variables in `loaderDeps`. Projects also keeps native `preload: false` so intent preloading cannot replace an expanded connection. Create refreshes with `router.invalidate({ sync: true })`. Edit uses its normalized mutation result and clears cached matches. Delete removes the Relay record and clears matches before navigation. Go supplies actual values from each request, so one declaration covers every slug in the route family. Pages using only Workspace data need its inherited result alone.

When renaming a route, its declaration moves with it. If a path parameter changes name, update the descriptor's `name`; its object key still names the GraphQL variable. Regenerate Relay artifacts after operation changes and use the [README validation sequence](../README.md#testing-the-built-application). The routing generator and Go serving code need no application-specific edits.

Directory routes and automatic splitting of colocated route components are native TanStack conventions. The versioned HTML metadata and consume-once replay belong to the adapter package; Acme retains its authentication-dependent initial-layout selection. `packages/route-adapter/src/static-routes.ts` adapts native generator metadata for Go. Keep that protocol separate from page UI and loader declarations.

The New and Edit files are `routes/_app/projects_/new/route.tsx` and `routes/_app/projects_/$projectSlug_/edit/route.tsx`. TanStack's trailing-underscore convention makes these sibling pages under `_app`, so they render without nesting inside the Projects or Project Detail page. Their native route IDs remain `/_app/projects_/new` and `/_app/projects_/$projectSlug_/edit`, while their URL paths omit the trailing underscores.

## Adapter package boundaries

The Go adapter serves each matched route's own document by default. `Options.Authenticated` controls private query execution. `Options.UseFallback` lets the application choose the fallback document independently, including for routes without queries. Acme supplies its signed-out page rule in `internal/server/bootstrap.go`. Public data pages can use their own route HTML with the default configuration.

`packages/route-adapter/` provides the TypeScript integration as an npm workspace, and `routeadapter/` provides Go serving. Vite imports `@acmekit/route-adapter/vite`. Runtime callers import `@acmekit/route-adapter/runtime`. Acme configures validation errors in `web/src/lib/route-query.ts` and provides Go callbacks from `internal/server/`. Directory routes own page UI and loader declarations, and shared project and authentication controls live in features. The TypeScript and Go packages share a versioned routing manifest and HTML metadata contract.

## Adapter and output size

Each route family adds one workspace loading HTML file and a manifest entry; all signed-out routes share the additional public `_shell.html`. All entries share the client JavaScript and stylesheet. The persisted-operation map is a separate binary input; request-specific bootstrap JSON adds only that page's declared responses to the document. Measure the current build and served response when evaluating size, since HTML files, response payloads, and compressed transfer sizes are different measurements.
