# Customize the template

Start from the [README local setup](../README.md#run-it-locally) and run its [full validation sequence](../README.md#testing-the-built-application) before extending the model. Try a maintainer mutation and a member session to establish the route → Relay → GraphQL → session → policy baseline.

## 1. Name the application

Update the module path in `go.mod` and its Go imports, the package metadata in `package.json`, and the visible Acme text in `web/src/`. Replace the brand assets in `web/public/` and the page metadata together so the tab title, navigation, and login view match.

Update `AcmeIcon`, `AcmeWordmark`, and the full `AcmeMark` together. The fixed sidebar uses the icon and lettering; the unboxed signed-out view uses the full logo. Follow the [branding and layout guide](design-system.md#workspace-layout-and-loading), keeping the assets' foreground-color rendering and applicable attribution.

The CLI name, environment variable prefix, and binary name are independent choices. If you change them, update `cmd/acme/`, `.air.toml`, `justfile`, `playwright.config.ts`, `.env.example`, and the README in the same change.

Retain the applicable copyright and license notices for any upstream assets or styles you keep.

The shared `routing` object in `vite.config.ts` supplies native Start settings to both Start and the route adapter. Set `srcDirectory` and `router` options there when changing the route structure. Acme supplies backend URL reservations and its signed-out document rule through application configuration. The reusable adapter's protocol uses `route-preloads` and `route-bootstrap` script IDs.

## 3. Change the GraphQL model

For a new field or operation:

1. Update the Go schema/resolver and the corresponding definition in `schema.graphql`.
2. Implement input validation, workspace scoping, and permission enforcement in Go.
3. Add or update Relay queries, fragments, or mutations in `web/src/`.
4. Regenerate the Relay artifacts and type-check the application using the [README commands](../README.md#commands).

Treat compiler output as generated code. Update the GraphQL source operations and run the compiler again instead of editing generated types. Development artifacts with query text live in `web/src/__generated__/`; `npm run relay:production` writes persisted artifacts to `web/build/__generated__/`, and the production build runs that step automatically. Optional `npm run relay:watch` uses Relay's native watcher and requires Watchman. Keep each page's query tag, `Route`, loader, page function, and pending function together in `route.tsx`. Reuse the query constant for the loader, reader, and Go `staticData.preloads`; import generated response types through `@relay`. Keep page functions unexported and move only shared controls into features. Native loaders use `fetchRouteQuery` with their abort signal to warm the Router-owned Environment; deferred readiness can keep page controls outside the data region's Suspense boundary. Workspace provides inherited authentication context through native `beforeLoad`; private child declarations use that context. Create synchronously invalidates loaders; edit uses Relay's normalized payload merge and clears cached matches; delete uses `@deleteRecord`, clears matches, and navigates. The [page guide](static-routing.md#adding-or-renaming-a-page) shows this pattern. Reusable Go HTML/bootstrap integration and route planning belong in the private `packages/route-adapter/` workspace, with explicit `/runtime` and `/vite` entry points. The Go `routeadapter/` package receives Acme authentication and GraphQL callbacks. Configure application validation errors through `web/src/lib/route-query.ts`. Keep separate production configurations and Relay output directories intact.

New Project needs only the inherited Workspace query. Edit's route colocates `ProjectEditPageQuery($slug: String!)`, its loader, reader, and authenticated preload declaration. The query composes `ProjectForm_project`, which owns `id`, `slug`, `name`, `description`, and `status`. Its deferred `fetchRouteQuery` uses `store-or-network` to reuse normalized Detail data. Bind GraphQL `slug` to the path's `projectSlug` in `staticData.preloads`. Preserve fragment spreads and timestamps in mutation responses so Relay updates existing readers.

Keep identifiers stable and globally distinguishable. When changing a connection, make its cursor behavior consistent with filtering and ordering. Update affected Go tests alongside the new behavior. The Playwright API test compares the running Go schema with `schema.graphql`, so keep both schema representations in the same change.

Project slugs stay stable through renames and remain reserved after deletion. The `new` slug is reserved for the creation route, so a project named New receives `new-2`. Detail and Edit resolve compatible legacy encoded IDs through `projectBySlug`, then replace their URLs with the corresponding canonical slug path while preserving query parameters and hash.

## 4. Change permissions

Update the embedded Rego policy and the trusted input constructed by Go. Keep the user role enum, the session representation, and frontend permission fields aligned.

UI visibility is helpful feedback. A caller can still send a mutation directly, so enforce the same rule in the resolver/service path. Exercise both an allowed request and a denied request when changing policy.

## 5. Add persistence when needed

The demo deliberately stores projects and sessions in memory. Choose your database and migration workflow before replacing that store. Persist users/workspaces as well as projects; durable projects need a durable ownership model.

SCS can use a database-backed session store independently of the project's repository. The frontend can keep its existing cookie-backed `viewer` flow. See [Architecture](architecture.md#persistent-storage) for the relevant SCS adapters.

Do not add a database URL to `.env.example` until code actually reads it. Keep the example configuration an accurate description of the running application.

## 6. Verify the embedded build

Run the [README full validation sequence](../README.md#testing-the-built-application). It covers both TypeScript configurations and Go build variants, Vitest, and Playwright against the embedded application.

After changing behavior, exercise both maintainer and member permissions, open a project detail URL directly, and refresh it. After visual changes, review the Components page and affected screens in light and dark mode. Keep bootstrap data private and verify that later reads still reach the API; the [static-routing contract](static-routing.md#initial-data-and-persisted-operations) explains that boundary.
